任务一 · 提示词工程师：让 AI 听懂需求

不写代码，写提示词；目标是让 AI 产出 effect 为 cube 的完整配置。

第 1 轮提示词

帮我写一段 Swiper 初始化代码，目标是 #wySw4 这个轮播：要能循环、能自动翻页、下面有圆点可以点，一开始就显示成立方体的效果。

第 1 轮 AI 回答

new Swiper('#wySw4', { effect: 'cube', autoplay: true, pagination: { el: '#wyPag4' }, });

第 1 轮的问题（粘进页面验证后逐条确认）

需求第 1 轮代码问题
无缝循环没有 loop翻到最后一张就停住，回不到第一张
3.2 秒自动翻页autoplay: true只能用默认 3000 ms，改不了 3.2 秒
手动操作后不停没有 disableOnInteraction: false用户拖一下，自动播放被永久暂停
圆点可点击pagination 缺 clickable圆点只能看，点了没反应

另外 speed 也没写，切换动画时长不受控制。

第 2 轮提示词（把需求拆成“参数名 + 取值”）

按下面 4 条硬性需求重写，每条都必须能在代码里找到对应参数，不要省略： ① 无缝循环 —— loop: true； ② 每 3.2 秒自动翻页，并且用户手动滑动之后自动播放要继续 —— autoplay: { delay: 3200, disableOnInteraction: false }； ③ 圆点分页器指向 #wyPag4 且能点击跳转 —— pagination: { el: '#wyPag4', clickable: true }； ④ 初始效果为立方体 —— effect: 'cube'。 额外：切换动画时长 800 毫秒。

第 2 轮 AI 回答（最终采用版本）

new Swiper('#wySw4', { loop: true, speed: 800, effect: 'cube', autoplay: { delay: 3200, disableOnInteraction: false, }, pagination: { el: '#wyPag4', clickable: true, }, });

验证与结论

把第 2 轮代码粘进页面（临时把初始 effect 设为 cube）→ 刷新 → F12 读取实例参数 → 截图。

参数实测：effect=cube、loop=true、delay=3200、disableOnInteraction=false、pagination.el=#wyPag4、clickable=true，全部命中。

结论：四项需求全部通过，循环、3.2 秒自动翻、拖完继续翻、圆点可点

答辩准备

第一版提示词漏掉了哪个需求？漏了“手动操作后自动播放不能停”，只写了 autoplay: true；另外 loop、clickable 也没写。

第二轮怎么“说清楚”的？不再用“要能自动翻页”这种自然语言，而是把每条需求直接翻译成参数名和取值，AI 没有自由发挥的空间。

AI 第一次给的代码错在哪？autoplay 用布尔值，无法控制延时，也不能保留手动操作后的继续播放；同时缺 loop、clickable、speed。

任务二 · creative 仿写：课堂没讲，AI 教你

课堂只讲了 6 种 effect，第 7 种 creative 靠读官方 demo 257-effect-creative.html 自学。

提示词 1

Swiper 的 effect 除了 slide / fade / cube / coverflow / flip / cards，还有没有别的？官方 demo 里有 257-effect-creative.html，它是怎么配置的？

AI 回答 1

有第 7 种：effect: 'creative'（自定义变换）。它必须配合 creativeEffect.prev / next 使用：prev 描述“上一张”在当前帧的位置，next 描述“下一张”的位置；每项可用 translate（[x, y, z]，x 可为百分比字符串）、rotate（[rx, ry, rz] 角度）、scale、opacity、shadow、origin。

提示词 2（追问）

那 prev 和 next 的 transform 具体各控制什么？当前正在看的那张受不受影响？

AI 回答 2

prev 控制已经翻过去、位于左侧的那张；next 控制还没进来、位于右侧的那张；当前 slide 本身始终是 identity（不位移、不旋转），所以三张的变换是分开配置的。

最终实现（演示四的 creative 分支）

if (ssc_effect === 'creative') { ssc_opt.creativeEffect = { prev: { shadow: true, translate: ['-55%', 0, -320], rotate: [0, 0, -8], scale: 0.8, }, next: { shadow: true, translate: ['60%', 0, -200], rotate: [0, 0, 8], scale: 1.1, }, }; }

prev：缩小到 0.8、向左移 55%、绕 Z 轴转 -8°、退到 -320px 景深，即“上一张缩小左移并带角度”。
next：放大到 1.1、从右侧 60% 位置、转 8° 进场，即“下一张放大右移进场”。两个都开了 shadow，卡片有投影，像电影选片墙。

答辩准备

transform 里的百分号是相对谁的？相对 slide 自身尺寸：translate 的第一个值（X）按 slide 自身宽度算，第二个值（Y）按自身高度算；Z 轴用 px，表示景深。不是相对容器宽度。

改一个数值让卡片转 20 度？把 prev.rotate 的第三个值（绕 Z 轴）从 -8 改成 -20，上一张就倾斜 20°。

② 超纲能力：keyboard 键盘控制（完整 AI 对话）

先让 AI 列出课堂没讲过的 4 种超纲能力并分析兼容性，再做选择。

提示词（选超纲能力）

Swiper 课堂只讲了 6 种 effect。keyboard / mousewheel / zoom / parallax 这 4 种超纲能力分别怎么配置？如果和 creative effect（自定义 3D 变换）同时启用会不会冲突？帮我推荐一种实现成本最低、演示效果最直接的。

AI 回答（关键内容摘录）

四种能力对比： ┌─────────────┬────────────────────┬──────────────────────────────┐ │ 能力 │ 配置方式 │ 与 creative 兼容性 │ ├─────────────┼────────────────────┼──────────────────────────────┤ │ keyboard │ { enabled:true, │ ✅ 无冲突，只监听方向键 ← → │ │ │ onlyInViewport:true}│ │ ├─────────────┼────────────────────┼──────────────────────────────┤ │ mousewheel │ { enabled:true, │ ⚠️ 会劫持页面滚动事件 │ │ │ threshold:30} │ 与浏览器滚动条冲突 │ ├─────────────┼────────────────────┼──────────────────────────────┤ │ zoom │ { maxRatio:2.5 } │ ❌ 与 3D 变换矩阵冲突 │ │ │ │ 放大时 creative 会失真 │ ├─────────────┼────────────────────┼──────────────────────────────┤ │ parallax │ { enabled:true } │ ⚠️ 需要给每个子元素加 │ │ │ │ data-swiper-parallax 属性 │ └─────────────┴────────────────────┴──────────────────────────────┘ 推荐 keyboard：只在轮播获焦后响应 ← / →， 不影响页面其他区域，与 creative 完全兼容。

最终代码（加入 ssc_fxOptions 公共配置）

keyboard: { enabled: true, onlyInViewport: true, },

实测：点一下演示四轮播 → 聚焦成功 → 按 → 键 → Swiper 的 realIndex 从 2 变为 3，翻页正常；页面其他位置按方向键不影响。

答辩四连问（全部围绕任务三）

1. 这段代码什么意思？ssc_fxOptions(effect) 是一个配置工厂函数：它返回一个包含 loop / speed / effect / autoplay / pagination / keyboard 的完整配置对象；如果传入的 effect 是 'creative'，再额外追加 creativeEffect 描述前后两张的 3D 变换。写工厂的好处是：7 个效果按钮切换时，只要改 btn.dataset.fx 就能生成新配置，不用复制 7 份几乎一样的对象。

2. AI 第一次给的哪里不对、你改了什么？AI 第一次只给了 keyboard: { enabled: true }，漏了 onlyInViewport: true。没这个开关时，只要页面里有任何一个 Swiper 带 keyboard，用户在其他地方按方向键也会触发轮播翻页。加上之后，只有轮播在可视区域内才响应键盘，不干扰页面其他交互。

3. 新参数的作用？keyboard.enabled —— 开启键盘方向键控制；keyboard.onlyInViewport —— 限制轮播只有在可视区域内才响应键盘，避免劫持全局方向键。选 keyboard 而不是 mousewheel / zoom / parallax，因为它与 creative 3D 效果完全兼容、实现最简洁（2 个参数）、演示最直观（按 ← → 立刻见效）。

4. 现场把 delay 改成指定值并解释预期变化。例如把 autoplay.delay 从 3200 改成 1000：每张只停留 1 秒就自动翻页，翻页节奏变为原来的 3.2 倍；disableOnInteraction: false 不变，所以即使你手动拖了一下松开，它仍会按 1 秒节奏继续翻。
